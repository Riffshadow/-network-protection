Условие

Проделайте атаку на настройку пароля для службы SSH:

bash
Копировать
hydra -L users.txt -P pass.txt <ip-адрес> ssh
ГИДРА: создайте два файла — users.txt (имена пользователей) и pass.txt (пароли). В нашем случае это могут быть случайные строки, но ради эксперимента можно добавить имя и пароль существующего пользователя.
Дополнительная информация по Hydra: https://kali.tools/?p=1847 .

Включение защиты SSH для Fail2Ban: Откройте файл /etc/fail2ban/jail.conf, найдите секцию [sshd] и установите параметр enabled = true.

Дополнительная информация по Fail2Ban: https://putty.org.ru/articles/fail2ban-ssh.html .

Результат: пришлите события, которые появились в логах Suricata и Fail2Ban, прокомментируйте результат.

Проведение атаки 🧠 (Скриншоты №A и B)

Атака была запущена из командной строки виртуальной машины virtualdva следующей командой.

Важно! Параметр -t 4 ограничивает количество одновременных соединений до четырёх. Это необходимо, чтобы дать демону SSH шанс записать попытки входа в системный журнал. Без этого параметра OpenSSH может сбрасывать соединения ещё до этапа аутентификации.

bash
Копировать
hydra -t 4 -L users.txt -P pass.txt ssh://192.168.56.102

Комментарий к результату Hydra: Ошибка [ERROR] could not connect to server: Connection refused означает, что соединение было сброшено на уровне протокола TCP/IP. Это произошло потому, что стандартный демон OpenSSH на Ubuntu очень агрессивно защищает себя от перебора паролей (MaxStartups). Он закрывает большинство попыток ещё на этапе установления соединения, не доходя до ввода пароля. Из-за этого в системном журнале /var/log/auth.log появляется мало записей типа Failed password. Однако несколько таких записей всё же попадают в журнал, так как часть соединений проходит через фильтр OpenSSH.
